# Implementation plans

Add a plan only after its matching proposal is accepted and the work spans multiple components or pull
requests. Name it `<issue-number>-<slug>.md`, link the PEP at the top, and include:

- The goal and chosen architecture.
- Exact files or components and their responsibilities.
- Public interfaces produced and consumed by each implementation slice.
- Dependency and rollout order, including compatibility constraints.
- Failure handling and rollback.
- Exact tests and acceptance evidence.

Plans are implementation blueprints. Track live status in the GitHub issue and pull requests instead of
maintaining a second task board here.
